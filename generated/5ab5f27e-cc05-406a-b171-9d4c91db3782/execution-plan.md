# Execution Plan

AgentCraft 2주 MVP 실행 계획 및 실행 산출물 (한국어, 실행 가능 버전)

1) 실행 목표 요약
- 목표: 예비 창업자와 초기 스타트업이 2주 내에 노코드 UI와 API를 동시 제공하는 경량 AI 에이전트 설계/구축 플랫폼의 MVP를 배포
- 핵심 구성: 템플릿 중심의 노코드 빌더 UI, 템플릿 기반 API 커넥터, 에이전트 템플릿/런타임
- 품질/보안: 기본 보안 준수(OAuth2/OIDC, TLS, 데이터 암호화, 감사 로그), 서버리스/다중 테넌시, 비용 관리 모듈
- 확장성: 모듈형 아키텍처로 Phase2에서 고급 워크플로우, 산업별 템플릿, 추가 커넥터 확장 가능

2) 상세 기술 계획 (아키텍처 및 구현 가이드)
- 모듈 구성
  - UI 빌더 모듈
    - 드래그앤드롭으로 에이전트 UI 구성
    - 템플릿 위젯 3종 이상 제공
    - 빌더에서 API 스펙 자동 생성 및 템플릿 저장
  - API 커넥터 모듈
    - 템플릿 레지스트리 + 매칭 로직
    - REST/GraphQL 커넥터 템플릿 2~3종 MVP 구현
    - OpenAPI/Swagger 기반 문서 자동화
  - 에이전트 템플릿/런타임 모듈
    - 2~3개 템플릿의 런타임 샌드박스 구현
    - 템플릿 런타임과 API 커넥터 간 바인딩 로직
  - 템플릿 라이브러리 모듈
    - MVP 템플릿 3~5종 제공, 신규 템플릿 추가 관리 체계 마련
  - 보안/컴플라이언스 모듈
    - OAuth2/OIDC 인증 및 권한 관리
    - TLS 전송 계층 보안, 저장 데이터 암호화
    - 최소 권한 원칙, 비밀 관리, 감사 로그 기본 제공
  - 관찰성(Observability) 모듈
    - 로깅/메트릭 수집, 경보 기본 체계
    - 간단한 대시보드 제공
  - 배포/비용 관리 모듈
    - 서버리스 기반 인프라, 다중 텐턴시 격리
    - 비용 모니터링 대시보드 및 무료 티어 정책 적용
- 기술 스택 제안
  - 프론트엔드: React + drag-and-drop 라이브러리(예: react-beautiful-dnd)
  - 백엔드: Node.js(NestJS 권장) 또는 Python( FastAPI) 기반 마이크로서비스
  - 서버리스 인프라: AWS Lambda / AWS Step Functions 또는 GCP Cloud Functions
  - API 스펙: OpenAPI 3.0 및 GraphQL
  - 데이터 저장: DynamoDB(또는 Firestore) + S3/Cloud Storage
  - 인증/보안: OAuth2/OIDC (Cognito/Auth0), TLS, KMS/Secret Manager
  - 로깅/모니터링: OpenTelemetry, CloudWatch/Stackdriver, Prometheus/Grafana
- 데이터 흐름 개요
  1) 사용자가 UI 빌더에서 템플릿 기반 에이전트를 구성
  2) 구성 정보가 백엔드의 템플릿 API 커넥터 레지스트리와 연결
  3) 에이전트 런타임은 샌드박스에서 실행되며 템플릿 런타임으로 바인딩
  4) 실행 로그/메트릭은 Observability 모듈로 전달되어 대시보드에 표시
  5) 보안 모듈이 인증/권한, 데이터 암호화 적용
- MVP 성공 기준(요건 매트릭스)
  - 템플릿 기반 UI 빌더가 3종 템플릿으로 구성, 저장/수정 가능
  - 템플릿 기반 API 커넥터가 최소 2종 연결 및 문서화
  - 에이전트 템플릿 2종 이상 런타임에서 실행
  - 기본 보안 구성(PKI/OAuth2/OIDC, TLS, 데이터 암호화, 감사 로그) 구현
  - 샘플 워크플로우 실행 및 로그 수집
  - 비용 모니터링 대시보드 및 무료 티어 정책 초기화

3) 2주 MVP 마일스톤 일정 (Day 기준; 14일 내 MVP 달성)
- Day 0: 준비 및 합의
  - MVP 성공 기준 재확인, 역할 분담, 커뮤니케이션 채널 확정
  - 코드 저장소 구조, CI/CD 파이프라인 선택
- Day 1–2: 인프라 및 모듈 골격
  - 모듈 간 인터페이스(API 스펙, 이벤트 포맷) 정의
  - 서버리스 인프라 기본 구성 및 보안 정책 초기 세팅
- Day 3–4: UI 빌더 MVP 개발
  - 템플릿 위젯 3종 설계/구현
  - 템플릿 기반 API 스펙 자동 생성 워크플로 구현
  - 샘플 템플릿 및 온보딩 가이드 초안 작성
- Day 5–6: API 커넥터 MVP 구축
  - 템플릿 레지스트리/매칭 로직 구현
  - REST/GraphQL 기본 커넥터 템플릿 2종 구현
  - API 문서 자동화(OpenAPI) 및 샘플 엔드포인트 연결
- Day 7–8: 에이전트 템플릿 및 런타임 MVP
  - 템플릿 2~3종 작성
  - 샌드박스 런타임 기본 구현
  - 샘플 워크플로우 구성
- Day 9: 보안 기본 구현
  - OAuth2/OIDC 연동 구성
  - TLS 설정 및 데이터 암호화 기본 적용
  - 감사 로그 기본 로직 구성
- Day 10: 관찰성 및 문서화
  - 로그/메트릭 수집 파이프라인 구성
  - 기본 대시보드 구성(주요 지표: API 호출 수, 에이전트 실행 성공/실패, 비용 추정)
  - 템플릿 가이드와 샘플 워크플로우 문서화 초안
- Day 11–12: 통합 테스트 및 디버깅
  - 엔드투엔드 시나리오 테스트(빌더 → 커넥터 → 런타임)
  - 보안 구성 재확인 및 경계 조건 테스트
- Day 13–14: MVP 완성과 시연 준비
  - MVP 데모 시나리오 최종 확정
  - 온보딩 흐름 최종 점검
  - 내부 피드백 수집 및 Phase2 로드맷 초안 제시
  - 릴리스 노트 및 운영 가이드 간단 작성

4) 배포 체크리스트 (배포 전/배포 당일 필수 확인)
- 코드/인프라
  - 소스 코드 버전 관리 정책 준수 여부 확인
  - IaC(옵션: Terraform/Pulumi)로 인프라 구성 자동화 및 버전 관리
  - CI/CD 파이프라인에서 빌드/테스트/배포 자동화 구성
  - 스테이징 환경에서 MVP 주요 플로우 완전 테스트
- 보안
  - OAuth2/OIDC 프로바이더 연결 정상 동작 여부 확인
  - TLS/암호화 키 관리 및 비밀 관리 도구 구성
  - 최소 권한 원칙 및 롤 기반 접근 제어 설정
  - 감사 로그 수집 및 무결성 검토
- 데이터/비용
  - 데이터 암호화 저장소 정책 적용 여부
  - 비용 모니터링 대시보드 활성화 및 경보 임계치 설정
  - 무료 티어 정책 문서화 및 초과 시 알림 흐름 구성
- 운영/관찰성
  - OpenTelemetry 설정 및 분산 트레이싱 활성화
  - 로그/메트릭 저장소 설정 및 로그 포맷 표준화
  - 대시보드 가시성 확보 및 주요 지표 모니터링
- 롤백/재해복구
  - 롤백 절차 문서화 및 자동화 가능한 경우 플래그 설정
  - 백업/복구 계획 수립
- UX/문서
  - 온보딩 흐름 최종 점검
  - 사용자 가이드, 템플릿 설명서, API 문서 최종 검수
- 고객 커뮤니케이션
  - MVP 릴리스 공지 및 간단한 ROI 메시지 정리

5) 관찰성(Observability) 전략
- 핵심 지표(KPIs)
  - API 호출 수, 성공률, 평균 응답 시간
  - 에이전트 런타임 실행 성공/실패 건수 및 실패 원인
  - 템플릿 로딩/구성 시간
  - 빌더 저장/배포 시간, 템플릿 생애 주기 지표
  - 비용 예측치와 실제 지출 차이
- 트레이싱
  - 분산 트레이싱(OpenTelemetry) 도입으로 UI Builder → API 커넥터 → 에이전트 런타임 흐름 추적
  - 코어 이벤트에 코리레이션ID 포함하여 연결성 유지
- 로깅
  - 구조화된 로그 포맷 사용(JSON), 범용 로그 레벨 설정(Debug/Info/Warn/Error)
  - 사용자 식별 정보 대신 익명화된 식별자 사용 및 개인정보 비식별화 정책 준수
  - 감사 로그: 인증/권한 변경, 자원 생성/수정/삭제 이벤트 기록
- 대시보드/알림
  - 운영 대시보드: API 호출(수/성공률/응답속도), 에이전트 런타임 상태, 템플릿 활용도, 비용 예측
  - 경보 정책: SLO 위반, 비용 임계치 초과, 비정상 활동 탐지 시 알림
- 데이터 보존 및 규정
  - 로깅/메트릭의 보관 주기(예: 90일) 및 컴플라이언스 준수 확인
  - 데이터 접근 제어 및 암호화 정책 주기적 검토
- 운영 가이드
  - 로그/메트릭 수집 위치, 대시보드 URL, 알림 채널(슬랙/메일/메신저) 명시
  - 장애 시나리오 및 복구 절차 문서화

6) 보안 및 컴플라이언스 기본 원칙
- 인증/인가: OAuth2/OIDC, RBAC 기반 권한 관리
- 데이터 보호: TLS 전송/저장 암호화, 비밀 관리 시스템 사용
- 격리 및 다중 테넌시: 데이터 격리, 테넌트 간 자원 격리
- 감사 로그: 모든 보안 관련 이벤트의 감사 로그 수집 및 보존
- 비밀 관리: 최소 권한 원칙에 부합하는 비밀 접근 정책
- 독립적 검증 로드맵: MVP에서 기본 준수, 이후 릴리스에서 추가 보안 검증 도입

7) 데이터 모델 요약(핵심 엔티티)
- User / Tenant: 다중 테넌시 사용자 및 소유 환경
- Template: 에이전트 템플릿 및 API 커넥터 템플릿의 정의
- APIConnector: 특정 API 연결 설정 및 스키마 정보
- AgentTemplate: 런타임 템플릿 정의(샌드박스 환경 포함)
- RuntimeInstance: 실행 중인 에이전트 런타임 인스턴스
- WorkflowLog: 실행 로그 및 메트릭 데이터
- SecurityContext: 인증/권한/세션 정보
- AuditLog: 감사 로그 항목

8) 시스템 블루프린트(요점)
- 아키텍처: 모듈화된 서버리스 경량 플랫폼, UI 빌더-템플릿-런타임-커넥터-보안-관찰성-비용 관리 모듈의 계층화
- 데이터 흐름 요약
  - 사용자 상호작용(빌더) → 백엔드 템플릿 레지스트리/커넥터 → 런타임 샌드박스에서 실행 → Observability로 로그/메트릭 전송 → 보안 모듈이 인증/암호화 적용
- 리스크 관리 포인트
  - MVP 범위 관리: 템플릿 중심으로 범위 제어
  - 보안/운영 리스크: MVP에서 기본 준수 후 점진적 심화
  - 비용 관리: 사용량 기반 모니터링 및 경보 체계 마련

9) Phase2 로드맷(확장 방향)
- 산업별 템플릿 확대: 업계 특화 템플릿(예: 핀테크/생산/리테일) 추가
- 고급 AI 워크플로우: 조건부 로직, 대화형 에이전트, 다중 API 연결 시퀀스
- API 커넥터 확장: 더 많은 외부 서비스의 템플릿과 커넥터 추가
- 마켓플레이스: 템플릿/에이전트 템플릿의 공유/구매 흐름 도입
- 고급 보안/컴플라이언스: 컴플라이언스 모듈 확장, 정기 보안 검증/감사

10) 팀 운영과 역할 제안
- PM/프로덕트 리드: MVP 스코프 관리, 로드맷 설계
- Tech Lead: 아키텍처 결정, 모듈 인터페이스 설계, 코드 품질 가이드
- 엔지니어링 팀: 프론트/백엔드 각각 개발, CI/CD/배포 파이프라인 구현
- 보안/컴플라이언스 리드: 보안 정책, 인증/권한, 감사 로그 설계 및 검증
- 디자이너: UX 템플릿 디자인, 온보딩 가이드, 문서화 UI 설계
- QA/테스트: 엔드투엔드 테스트, 보안 테스트, 성능 테스트

참고 및 의사결정 포인트
- MVP의 중점은 템플릿 기반의 노코드 빌더와 템플릿 기반 API 커넥터를 중심으로, 에이전트 런타임은 템플릿 중심으로 제공하는 것이다. API 자동생성은 템플릿 중심으로 제한하고, Phase2에서 확장한다.
- 보안은 MVP에서도 기본 준수하되 독립 검증은 이후 릴리스에서 강화한다.
- 비용 관리 대시보드와 무료 티어 정책은 MVP부터 적용해 초기 비용 예측과 관리가 가능하도록 한다.
- Phase2의 차별화 포인트는 업계별 템플릿, 더 넓은 API 커넥터 생태계, 고급 워크플로우로 설계한다.

필수 산출물(초안)
