# Execution Plan

AgentCraft 2주 MVP 실행 계획 (한국어 실행 출력)

1) 핵심 합의 요약
- MVP 목표: 2주 내 3–5개의 핵심 기능으로 빠르게 시장에 출시하되 품질과 보안을 기본적으로 확보한다.
- 아키텍처 방향: API 우선 엔진(core) + 템플릿 기반의 노코드 UI를 중심으로 구성. MVP 1.0은 템플릿/블록 중심의 UI와 API 우선 엔진으로 구성하고, 노코드 UI는 Beta로 운영한다.
- 인프라 방향: 서버리스/관리형 services 중심으로 클라우드 비용 최소화 및 확장성 확보.
- 보안 및 거버넌스: 인증/인가, 데이터 암호화, 감사 로그를 MVP에 반영하고, 간단한 거버넌스 문서를 제공한다.
- 확장 계획: Phase 1 이후 Phase 2에서 노코드 UI 확장, 추가 템플릿/커넥터, 고도화된 워크플로우를 추진한다.
- 차별화 포인트: 템플릿 기반 엔진 + 빠른 학습 루프를 통해 예비 창업자들의 초기 구성 속도 향상.

2) 시스템 아키텍처 개요
- API 우선 엔진 코어
  - 기능: 에이전트 정의 생성/수정/삭제, 실행 관리, 상태 추적, 로그 수집
  - 모듈화: Agent Core, Workflow Core, Connector Core로 분리하여 재사용성 확보
- 프런트 엔진
  - 노코드 UI 레이어(Beta): 템플릿 기반 빌더, 드래그-앤-드롭 인터페이스 일부
  - 원클릭 연동 프레임워크의 초기 프로토타입
- 런타임/에이전트 실행
  - 경량 서버리스 런타임으로 에이전트 실행 관리
  - 다중 테넌시 데이터 격리 및 자원 관리
- 데이터 저장소
  - 관계형 DB(예: PostgreSQL) + 필요시 NoSQL(예: DynamoDB) 조합
  - 로그/메트릭 저장용 분리 저장소
- 보안/거버넌스
  - 인증/인가(Role-Based Access Control), 데이터 암호화(전송/저장), 감사 로그 저장
  - MVP 수준의 간단 거버넌스 문서 및 정책
- 운영/관측성
  - 로깅/메트릭/알림 시스템
  - 비용 모니터링 및 예산 경고
- 배포/배포 파이프라인
  - CI/CD 파이프라인으로 MVP 배포/롤백 가능성 확보
  - IaC(Infrastructure as Code)로 인프라 재현성 확보

3) 상세 기술 계획
- 기술 스택 제안(권장, 필요에 따라 유연하게 변경)
  - 백엔드: TypeScript(Node.js) 기반의 마이크로서비스 구조(NestJS 권장)
  - 엔진 구성: Agent Core, Workflow Core, Connector Core 모듈화
  - 프런트: React 기반의 템플릿 빌더(Beta)
  - 런타임: Сервер리스(Lambda/Cloud Run) 기반 에이전트 실행
  - 데이터 저장: PostgreSQL(주 데이터), Redis(캐시/작업 대기 큐), DynamoDB/Firestore 보완
  - 인증/인가: Cognito/Auth0 또는 OIDC 공급자
  - 커넥터: 표준 API 커넥터 라이브러리(REST/gRPC 기반), 템플릿으로 미리 구성
  - 관측성: OpenTelemetry + Prometheus + Grafana + Loki 조합
  - 저장소/스토리지: S3/Blob Storage
  - CI/CD/IaC: GitHub Actions + Terraform/Pulumi
- 데이터 모델 개요
  - Tenant: 다중 텐넌시를 위한 구분 단위
  - User: 사용자 계정 및 역할
  - AgentDefinition: 에이전트의 스키마(이름, 버전, 권한, 기본 로직)
  - Workflow: 워크플로우 정의(노출되는 순서, 트리거, 조건)
  - Run: 에이전트 실행 인스턴스의 실행 기록
  - Template: 노코드 빌더의 템플릿/블록 모듈
  - Connector: 외부 API 커넥터 정의
  - AuditLog: 인증/권한 변화, 데이터 변경 이력
- API 엔진 코어 설계(핵심 엔드포인트 예시)
  - POST /agents: 에이전트 정의 생성
  - GET /agents/{id}: 에이전트 정보 조회
  - PUT /agents/{id}: 에이전트 수정
  - DELETE /agents/{id}: 에이전트 삭제
  - POST /agents/{id}/run: 에이전트 실행 시작
  - GET /workflows/{id}: 워크플로우 조회
  - POST /connectors: 외부 커넥터 등록
  - POST /templates/:templateId/publish: 템플릿 게시
- 템플릿 UI(Beta) 및 템플릿/블록 예시
  - 기본 템플릿 3–5개: 메시지 전달 에이전트, 데이터 수집 워크플로우, 단순 의사결정 에이전트
  - 블록 구성: 입력 수집, 조건 분기, 외부 호출, 데이터 저장, 로그 남김
  - 노코드 UI Beta에서 커넥터 자동 연결의 초기 흐름 제공
- 보안 기본 준수
  - 인증/인가: 역할 기반 접근 제어, 최소 권한 원칙
  - 데이터 보호: 전송 시 TLS, 저장 시 암호화
  - 감사 로깅: 중요한 액션의 변경 이력 저장
  - 거버넌스: 간단한 데이터 정책/보안 원칙/변경 관리 문서
- 관측성 및 로깅/모니터링
  - 메트릭: API 응답 시간, 에러율, 실행 대기 시간, 큐 길이, 로그 수집 속도
  - 트레이싱: 분산 트레이싱(OpenTelemetry)으로 엔드투엔드 추적
  - 로그: 구조화 로그 및 중앙 로그 저장소
  - 대시보드: Grafana 대시보드로 SLI/SLO 모니터링
- 배포 및 롤백 전략
  - 단계적 배포: 스테이징 -> 카나리(일부 사용자) -> 전체 배포
  - 롤백: 실패 시 즉시 이전 버전으로 롤백 가능하도록 버전 관리
  - 테스트: 단위/통합/보안 스캐너 자동화
- Phase 1 vs Phase 2 분리
  - Phase 1: API 엔진 안정화, 기본 템플릿/블록 제공, 3–5개의 커넥터 도입, 템플릿 기반 UI Beta
  - Phase 2: 노코드 UI 확장, 더 많은 커넥터, 고도화된 워크플로우, 성능/확장성 개선

4) 2주 MVP 마일스톤 일정
전제: MVP 범위는 핵심 기능 3–5개, 템플릿 기반 UI(Beta), API 엔진 안정화, 보안 기본 준수 포함.

- Day 0–1: 재정의 및 상세 스코프 확정
  - MVP 핵심 기능 3–5개 확정
  - 성공 지표(KPIs) 정의: 응답 속도, 실패 비율, 로그/감사 추적 가용성, 피드백 수집 지표
  - 역할/담당자 확정
- Day 2–3: 인프라/CI-CD 기초 세팅
  - 저장소, IaC 템플릿 구성
  - 기본 보안 설정(인증/인가 프로토타입, 암호화 설정, 로그 수집 경로)
- Day 4–5: API 엔진 코어 뼈대 구축
  - 엔진 핵심 엔드포인트 설계
  - 모듈화된 구조 구축
- Day 6–7: 인증/인가, 데이터 보안, 감사 로깅 구현
  - MVP 수준의 인증/인가 도입
  - 암호화 설정 및 로그 포맷
- Day 8–9: API 커넥터 프레임워크 설계
  - 표준 커넥터 골격 5–7개 설계
  - 템플릿 기반 빌더의 커넥터 호출 흐름 프로토타입
- Day 10–11: 템플릿 기반 노코드 UI Beta 구현
  - 템플릿/블록 3–5개 제공
  - 원클릭 연결 프레임워크의 프로토타입
  - 드래그-앤-드롭 인터랙션 기본 구현
- Day 12: 품질/보안 테스트 및 관측성 추가
  - 단위/통합 테스트, 보안 스캐너
  - 로깅/메트릭 대시보드 구성
- Day 13: MVP 문서화 및 준비
  - 사용 가이드, 설치/배포 가이드, 거버넌스 요약 문서
  - 초기 고객 피드백 수집 플랜
- Day 14: MVP 릴리스 및 마켓 접근 준비
  - 초기 고객 대상 시범 론칭
  - 피드백 루프 설계 및 개선 로드맷 확정

Phase 1/Phase 2 로드맹
- Phase 1: API 엔진 안정화 + 템플릿 빌더(Beta) + 기본 커넥터
- Phase 2: 노코드 UI 확장, 추가 커넥터, 고도화된 워크플로우, 성능 개선

6) 관측성 전략
- 목표 서비스 수준(SLO) 및 지표
  - API 응답 시간(90th percentile): 예) 2초 이하
  - API 에러 비율: < 0.5%
  - 에이전트 실행 성공률: > 98%
  - 워크플로우 처리 지연 시간: 95th percentile 기준
  - 로그 수집/저장 지연: < 1분 이내
  - 비용 예산 준수: 월 예산 대비 초과율 경고 기준
- 지표/로그/트레이싱 구성
  - 분산 트레이싱: OpenTelemetry로 엔드투엔드 흐름 추적
  - 메트릭: Prometheus로 각 서비스의 메트릭 수집
  - 로그: 구조화 로그를 Loki에 수집, 중요한 이벤트는 태깅
  - 대시보드: Grafana에서 API 성능, 엔진 상태, 워크플로우 진행 상황, 커넥터 상태를 실시간 시각화
- 알림 정책
  - 슬랙/메일/SMS 알림 채널 설정
  - 임계값 초과 시 즉시 알림, 복구 시 해제
  - 정기 점검 일정 자동 알림
- 가용성/데이터 보호
  - 백업 주기 및 보존 정책 수립
  - 데이터 복구 시나리오 테스트
- 운영 측면
  - 자동화된 테스트 실행 및 배포를 통한 안전성 확보
  - 로그 보관 기간 정책에 따라 데이터 저장소 조정
  - 모듈화된 구성으로 특정 컴포넌트만 롤링 업데이트 가능

7) 리스크 관리 및 의사결정 포인트
- 범위 관리: MVP 3–5개 핵심 기능으로 엄격히 제한, Phase 2로 확장
- 품질/안정성: 초기 MVP에서도 핵심 보안 준수 및 테스트 자동화 우선
- 학습 곡선: 템플릿 기반의 노코드 UI로 학습 곡선을 낮추되, 고도화된 커스텀 로직은 Phase 2에서 다루도록 분리
- 비용 관리: 서버리스/관리형 인프라로 비용 최소화, 모듈별 비용 모니터링
- 차별화 포인트: 템플릿 기반 엔진과 빠른 학습 루프를 중심으로 시장에서의 차별화를 명확히

8) 다음 단계 및 의사결정 포인트
- 기술 스택 최종 확정: Node.js/TypeScript 기반 엔진, 서버리스 런타임, PostgreSQL + Redis 조합
- MVP 스코프 확정: 3–5개 핵심 기능과 3–5개 템플릿/블록
- 템플릿/커넥터 우선 순위 선정: 초기 최소 커넥터 목록 확정
- Phase 2 로드맹 초안: UI 확장/고도화 로드맹에 대한 주요 기능 목록 및 일정 제시
- 보안 거버넌스 경량 문서 완료 및 공유

요약
- AgentCraft의 2주 MVP는 API 우선 엔진 + 템플릿 기반 노코드 UI의 결합으로 구현되며, 서버리스 기반 비용 절감, 기본 보안 준수, 간단한 거버넌스 문서를 포함합니다.
- 2주 실행 로드맵은 Day 0에서 Day 14까지의 구체적인 작업 분량과 산출물을 제시합니다.
